# AgentShop

The showcase app for [AgentCtl](../../README.md): a small but complete shop whose 105 scenario files run
**unchanged** on both ports. It is the Kotlin port of agentctl-ios's `Examples/AgentShop` (the TCA app), screen
for screen and command for command, and every scenario prints the same bytes here as it does there.

| Group | Screens | Scenarios |
|---|---|---|
| **Authentication** | login, one-time code, sign-up, email verification, password reset, profile and log-out | 35 |
| **Onboarding** | welcome carousel, interests (2–4), shipping address, notifications — once per new account | 26 |
| **Shop** | feed (filter, search, sort), product (sizes, quantity, favorite), cart (promo codes), checkout (saved address, express shipping, card or Apple Pay), confirmation, orders | 44 |

Everything behind the screens is mocked in memory (`shop/…/clients`), and every mocked call can be made to fail
from a script (`mock orders.placeOrder network`). The accounts:

| Account | Password | |
|---|---|---|
| `alice@example.com` | `Passw0rd!` | onboarded, three orders, a saved address |
| `bob@example.com` | `Hunter22x` | onboarded, no orders, no address |
| `nina@example.com` | `Passw0rd!` | not onboarded yet: signing in starts onboarding |
| `locked@example.com` | any | always locked |

Promo codes `SAVE10` and `HALF`; card `4000 0000 0000 0002` is always declined. The full command reference is
[`agent-commands.md`](agent-commands.md), generated from the screens' agent declarations (`*Agent` objects).

## Headless mode

On the JVM, no emulator, no views:

```bash
cd examples/agentshop
./appctl test                                        # all 105 scenarios
./appctl test scenarios/shop-checkout-happy-path.appctl
./appctl run "login-as alice; tab orders; open 1003; cancel"
./appctl run "use-otp; email alice@example.com; send; advance 30s; resend"
./appctl screens                                     # every screen, command and summary key
./appctl docs --check                                # agent-commands.md is current
```

```
$ ./appctl run "login-as alice; tab orders; open 1003; cancel"
```

The wrapper rebuilds `shopctl` (Gradle's `installDist`) and runs it with `APPCTL_ROOT` set to this directory, so
the config's paths (`scenarios`, `agent-commands.md`) resolve here from any working directory; a scenario file
given to `test` is relative to the working directory. `check`'s
Gradle tasks go through [`gradlew`](gradlew) here, which forwards to the repository's wrapper.

### Parity with the Swift reference

[`IosParityTest`](ctl/src/test/kotlin/io/github/olbartek/agentctl/examples/agentshop/ctl/IosParityTest.kt) runs every
scenario through this port's CLI and compares the output, byte for byte, with the reference's `shopctl` transcripts
in `ctl/src/test/resources/ios/`, and `screens` with its `screens`. After a change on the Swift side, regenerate them
from a sibling agentctl-ios checkout:

```bash
examples/agentshop/bench/ios_transcripts.sh            # or: … path/to/agentctl-ios
```

`agent-commands.md` differs from the reference's in two lines, both written by the library rather than the app: the
"generated by" note names the screens' agent declarations instead of the `+Agent.swift` files, and the runtime
`advance` command's help follows this port's runtime.

## Layout

| Path | What |
|---|---|
| `shop/` | `:examples:agentshop:shop`: the app's logic, which ships in the release app and depends on `agentctl-core` only. Packages mirror the reference's modules: `models`, `clients` (the mocked clients and their in-memory backends, `MockAccounts`, `SessionStorage`), `auth`, `onboarding`, `shop`, `home`, `app` (`AppFeature`, the root, and `AgentShop.store`), plus `navigation` (the stack the containers push screens on). |
| `shop/…/<feature>/<Screen>.kt` | Each screen's state, actions and reducer, and beside it its agent surface (`<Screen>Agent`): path, summary, commands. |
| `ctl/` | `:examples:agentshop:ctl`: `AgentShopConfig`, the whole AgentCtl integration — one `AppCtlConfig`, and the headless and live hosts — and the tests that drive AgentShop through it. |
| `shopctl/` | `:examples:agentshop:shopctl`: the CLI executable (`shopctl`). |
| `scenarios/` | `<group>-<name>.appctl`, 105 of them, byte for byte the reference's. |
| `bench/` | `ios_transcripts.sh`, which regenerates the reference transcripts the parity test compares against. |
| `appctl` | The wrapper: rebuilds `shopctl`, then runs it with this directory as the root. |
| `gradlew` | Forwards to the repository's Gradle wrapper, for `check` and `app launch`. |

### How the logic is shaped

The reference's TCA reducers become `agentctl-core` `Reducer`s over immutable `data class` states and `sealed
interface` actions, so a Compose UI renders a `StateFlow` and sends actions:

- `AgentShop.store(environment, sessionStorage, scheduledFaults)` builds the store on an `AgentEnvironment` (the
  headless host's, the live host's, or `AgentEnvironment.system(scope)` in a release build).
- `AppFeature.State` is `Launching`, `Auth`, `Onboarding` or `Home`; each screen's state is reached through its
  container's state, and its actions through the container's (`AppFeature.Action.Home(HomeTabs.Action.Cart(…))`).
- TCA's `@Dependency` values are an explicit `ShopDependencies`, built from the environment: the clock, the UUIDs,
  and the mocked clients. Nothing reads real time, randomness or the locale except through it; the auth server
  measures codes' age on an `uptime` the headless host drives from its virtual clock, so `advance 5m` expires them.
- A screen never navigates by itself: it sends a `Delegate` action, which its container turns into a push, a pop or
  a tab switch. Stacks (`navigation.Stack`) scope each pushed screen's effects and cancel them when it is popped, and
  leaving a case of `AppFeature` cancels that case's effects, as TCA's `forEach` and `ifCaseLet` do.
